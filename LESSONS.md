# Verified lessons

- React checkbox onChange follows its click/change plugin path. Programmatic input/change events alone are insufficient for controlled checkbox integration. The sandbox needs a native event adapter and a browser regression test.
- The event rules state age-of-majority eligibility. They do not state a parental-consent exception. See docs/SUBMISSION.md for dated links and discrepancies.
- Windows symbolic-link creation is unavailable under this process token. CLAUDE.md uses the supported @AGENTS.md import fallback.
- Chromium's automatic side-panel action path did not grant activeTab in the tested build. An explicit action.onClicked handler that calls sidePanel.open granted temporary access. The actual extension test verifies denial before the action and successful injection after it without broad host permissions.
- In Chromium 159's isolated world, deferred CSSOM serialization could recreate an empty style attribute after removal. Reading the style attribute immediately before removing an originally absent attribute produced exact rollback on the public W3C demonstration. Keep this real-browser regression separate from JSDOM tests.
- Host-controlled data-clearview-id attributes cannot establish element identity. An internal WeakMap prevents copied attributes from redirecting repairs to replacement nodes.
- Raw outerHTML is unsafe evidence for form controls because it can contain value attributes. Reports use safe element descriptions and exclude input, textarea, and editable-field values.
- A root Vite 6 override keeps the React Vite plugin and workspace config on the same type definitions. This also removes the nested Vite 5 development-server dependency from Vitest 2.
- Control height alone does not establish a usable target. The previous All filter was about17px wide despite sufficient height. Check both dimensions in browser tests.
- A two-column currency total can overlap when text grows. Intrinsic wrapping and a stacked phone layout preserve exact amounts; a diagnostic doubled-text check covers this failure separately from browser zoom.
- Inline themed SVGs need unique mask and gradient identifiers. Spotkit artwork uses React useId, and its source SVG remains available for the geometry checker.

## Consumer-flow and daylight lessons — November 27

- In ClearView's consumer audit, shared sentence-level cadence turned a $49 setup fee plus $20/month into $69/month. Bind each price to its own units and clause. Annual equivalents, per-unit prices, credits, refunds, and explicit foreign currencies need separate treatment.
- A checked property does not establish who selected a choice. Required subscription consent was incorrectly cleared by a keyword-only repair. ClearView now separates detection from mutation eligibility and requires explicit selected-action review.
- Internal node identity prevents copied-ID substitution but not same-node purpose changes. A report-time evidence fingerprint and current eligibility check address that separate boundary.
- A host can reject a synthetic checkbox change or alter a field later. Read back the result, reconcile asynchronous changes on rescan, and report conflicts. Compare-and-restore preserves later host attributes; exact original rollback remains valid for unchanged pages.
- Action counts and node counts are different. One source can have multiple findings; one visibility repair can also adjust opacity ancestors. `repairSummary.nodes` counts unique current owned targets, not historical applied actions.
- A lower monthly total did not prove an add-on was removed. The web receipt now requires selected DP-001 provenance, the same checkbox and source, unchanged terms, and a currently unchecked choice before showing removal attribution.
- A delayed local-file import could override a later scenario choice. Reset and navigation must invalidate the import token. Responsive visibility changes also require a new live scan; an already-open repair review stays immutable.
- For the daylight palette, `#B91C1C` on `#FEF2F2` and `#92400E` on `#FFFBEB` do not reach the requested 7:1 body-text target. The selected darker text colors `#991B1B` and `#78350F` reach 7.596644:1 and 8.748451:1 respectively. Border and accent colors can remain separate from body text.
- GOV.UK's current standard body scale is 19 px. ClearView's owner-requested 16 px body is an explicit design choice, not a claim that the GOV.UK scale was copied. Apple typography guidance informs hierarchy and legibility without making native point sizes into web pixel requirements.
- A source build, calculated contrast, an axe result, automated Chromium, and visible testing in the owner's installed Chrome are distinct evidence. Keep their results and pending states separate. Historical dark-revision tests do not become daylight passes without a rerun.
- Axe custom contrast options must be configured through top-level `checks`, not nested `rules.any` objects. The latter retained the default threshold in this installed version. A controlled `#666` on white specimen now verifies that normal and large text both fail the requested 7:1 threshold, while `#111827` passes.
- A sticky dialog footer covered focused choices at both 375 px and 1440 px. Native Tab navigation exposed the obstruction that a simple focus-ring check missed. The review footer now stays in normal flow, and the browser suite checks focused controls against its bounds.
- Repair annotations are part of ClearView's own UI. The old 10 px labels violated its 14 px metadata floor. Compact 14 px checkmarks preserve the annotation without adding long text to tight host rows; repaired text uses at least 16 px and preserves larger computed sizes.
- Automatic rescans must not dismiss unrelated errors. A deployed test exposed an import error being cleared by a later scan. Only an explicit Rescan clears that error now; the regression changes a real checkbox and waits for the receipt update before asserting the import error is still visible.
